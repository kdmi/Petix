# $PETIX: вывод и ввод (feature 019) — как это работает и что делать оператору

Схема custodial (уточнена 2026-09-17): монеты лежат на **кошельке запуска** (`TOKEN_PAYOUT_SOURCE`) и не покидают его. Серверный **оператор** (`TOKEN_TREASURY_SECRET`) один раз получает от кошелька запуска `approve` на недельный бюджет и при выводе делает `transferFrom(кошелёк запуска → игрок)`, платя комиссию своим ETH; игрок ничего не подписывает, ключ кошелька запуска на сервере не хранится. Доступно к выплате = min(баланс кошелька запуска, остаток разрешения). Ввод — обычный перевод монет **на кошелёк запуска**. Без `TOKEN_PAYOUT_SOURCE` оператор сам хранит монеты (старый режим). Адреса и ключи живут только в env (`TOKEN_*`), в репозитории их нет (тест `tests/unit/token-no-addresses.test.js`).

## Вывод

1. `POST /api/token/withdraw-request { amount }` — проверки: сессия EVM, флаг `TOKEN_ENABLED`, режим `WITHDRAW_ENABLED` (0 = только админ), `MIN_WITHDRAW`, `WITHDRAW_MAX_PER_TX` (0 = выкл), баланс; предполёт раздатчика (монет ≥ сумма, ETH ≥ `TOKEN_MIN_GAS_ETH`, `estimateGas`).
2. Points списываются атомарно, запись `reserved` в `profile.withdrawals`.
3. Под глобальной блокировкой отправки (`token-store.sendLock`, CAS) берётся nonce `pending`, отправляется ERC-20 `transfer`; конфликт nonce → один повтор. Запись → `sent` (txHash, nonce).
4. До 8 с ждём receipt: `status 1` → `confirmed`; `status 0` → `failed` + возврат Points; иначе остаётся `sent`.

### Статусы заявки и когда Points возвращаются

| Статус | Что значит | Points |
|---|---|---|
| `reserved` | списаны, транзакция ещё не ушла (лямбда могла умереть) | вернутся через 2 мин при реконсиляции |
| `sent` | транзакция отправлена, ждём сеть | списаны |
| `confirmed` | сеть подтвердила | списаны навсегда |
| `failed` | отправка упала или receipt.status = 0 | возвращены |
| `dropped` | receipt нет, а следующий nonce раздатчика уже прошёл, прошло ≥ 2 мин | возвращены |

Реконсиляция ленивая: при `GET /api/token/config`, `POST /api/token/withdraw-status {id}` и в cron `sync` (для недавно активных кошельков). Никаких возвратов «по таймеру» без данных сети.

### Гейт по капсуле (добавлено 2026-09-17)

`WITHDRAW_REQUIRE_NFT=1` (по умолчанию): выводить может только кошелёк, на котором **хотя бы одна капсула коллекции лежит ≥ `WITHDRAW_NFT_HOLD_HOURS` (36)** часов. Отсчёт — от **времени блока**, в котором капсула пришла на кошелёк; индексатор капсул (`nft-store.ownedSince`, крон `/api/nft/sync`) хранит его для каждого токена и обновляет при каждой передаче, сжигание стирает. Для капсул, проиндексированных до появления поля, время восстанавливается разовым бэкфиллом при первом синке (`ownedSinceBackfilledAt`). В момент вывода дополнительно проверяется живой `ownerOf` квалифицирующей капсулы — продажа минуту назад отклоняет вывод, даже если индекс ещё не обновился. Админы освобождены. Причины в `config.reason` и ответах 403: `NFT_REQUIRED`, `NFT_HOLD_TOO_SHORT` (+`eligibleAt`), `NFT_INDEX_UNAVAILABLE` (контур NFT выключен или RPC лежит). Порог минимального вывода — `MIN_WITHDRAW` = 1 000.

## Ввод

Игрок переводит монеты на адрес раздатчика (кнопка «Send from wallet» или копирует адрес). Зачисление 1:1 целыми монетами профилю **адреса-отправителя**:
- быстрый путь — `POST /api/token/deposit-confirm { txHash }` по receipt (202 пока подтверждений < `TOKEN_CONFIRMATIONS`);
- фон — cron `GET /api/token/sync` раз в минуту сканирует `Transfer(to = раздатчик)` от курсора до `latest − confirmations`, не больше `TOKEN_SYNC_MAX_BLOCKS` за прогон.
Идемпотентность: ключ `txHash:logIndex` в `profile.deposits` + `recentKeys` в глобальном состоянии. Переводы с `TOKEN_INTERNAL_WALLETS` (холодный, одноразовый) — пополнения, не вводы. Перевод с биржи зачисляется адресу биржи — это написано в UI, вручную не возвращаем.

## Админка (Economy → «$PETIX treasury», `GET /api/admin/token-stats`)

Остаток монет и ETH раздатчика, выведено/внесено за сутки, заявки в полёте, выплачено за 7 дней, курсор синка и последняя ошибка, журнал операций со ссылками на обозреватель. Предупреждения: `lowGas` (ETH < 0,01), `lowTokens` (монет меньше выплат за 7 дней), ошибка синка.

## Что делать оператору

- **`lowGas`** — докинуть ETH на раздатчик (адрес в админке). Пока ETH ниже `TOKEN_MIN_GAS_ETH`, выводы отклоняются без списания.
- **`lowAllowance` / `INSUFFICIENT_TREASURY` при полном кошельке запуска** — разрешение оператору кончается: с кошелька запуска выполнить `approve(оператор, новый бюджет)` на контракте монеты (в MetaMask: контракт монеты → Write → approve). Никаких переводов монет не нужно.
- **`lowTokens`** — на кошельке запуска монет меньше, чем выплачено за 7 дней: докупить/пополнить кошелёк запуска. Переводы с оператора и с самого кошелька запуска вводами не считаются.
- **`lastError` в синке** — обычно RPC (лимиты Alchemy). Курсор не сдвигается, следующий прогон повторит. Если ошибка держится — проверить `TOKEN_RPC_URL`.
- **Много `sent` без подтверждения** — посмотреть `sendLock` и nonce раздатчика в админке; застрявшая транзакция в mempool блокирует следующие. Ускорить/заменить её из кошелька раздатчика вручную (тот же nonce, выше газ); реконсиляция потом сама разберётся по receipt.
- **Подозрение на утечку ключа оператора** — `WITHDRAW_ENABLED=0` в админке (мгновенно), с кошелька запуска `approve(старый оператор, 0)` (отзыв), новый оператор → `TOKEN_TREASURY_SECRET` + новый `approve`. Потери ограничены остатком разрешения. Адрес пополнения (кошелёк запуска) не меняется, курсор синка не сбрасывается.
- **Смена монеты (тест → бой)** — поменять `TOKEN_CONTRACT`, `TOKEN_START_BLOCK`; курсор сбросится сам.
- **Полный откат** — `TOKEN_ENABLED=0`: маршруты отвечают 404, крон — `skipped`, вход в UI исчезает; заявки `sent` досчитаются при следующем включении.

Предполёт перед любым включением: `node scripts/token/preflight.js --eth-usd <цена ETH>`.
